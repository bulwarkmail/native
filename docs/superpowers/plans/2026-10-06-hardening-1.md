# Hardening Pass 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the open follow-ups from phases 1–4b that can lose data, send or sync against the wrong account, or wrongly treat the app as offline. Also fix a few small, clear bugs in the same areas.

**Architecture:** Each task is a small, self-contained fix with its own tests. Task 1 is the only one that changes a shared input. It replaces the app's "online" signal for send and sync decisions: today that signal is Android's internet-reachability probe. From Task 1 on, decisions use a combination of the network interface state and whether the mail server answered recently. Every other task stays inside one module.

**Tech Stack:** React Native / Expo, TypeScript, Zustand, AsyncStorage, vitest (`npm test`), JMAP (RFC 8620/8621, Sieve, `PushSubscription`, JSContact).

**Spec:** The follow-up sections of [2026-10-04-webmail-parity-roadmap.md](2026-10-04-webmail-parity-roadmap.md): Phase 1, 2, 3, 4a and 4b follow-ups. Each task quotes the line it closes. Task 1 also comes from the device test of 2026-10-06. The mail server was on the local network, and Android's internet-reachability probe can report "not reachable" while that server answers. Since Phase 4b, the app would then queue sends that never go out.

## Global Constraints

- **Branch:** `parity/hardening-1`, created from `main` at `809acb9`.
- **Gate on every commit:** `npm run typecheck && npm test && npm run i18n:check`.
- **Strings:** use `t('key', 'English fallback')`. App-only keys go in `locales/rn/en.json`. Run `npm run i18n:harvest`.
- **Commits:** one per task, with the task's subject and the `Co-Authored-By:` and `Claude-Session:` trailers. Stage files by explicit path.
- **Parity docs:** do not edit `docs/parity/*.md` or `PARITY_CHECKLIST.md` in a task.
- **Tests:** vitest runs `src/**/__tests__/**/*.test.ts` in node, with no React Native render harness. Write tests first and record RED.
- **Storage:** never delete `webmail:outbox:v1:*` keys. Never weaken the send queue's rules: never send twice, never send from the wrong account, never drop a message silently.
- **Accounts:** every account-scoped call passes its account explicitly. Any async work that can outlive an account switch re-checks the account before it writes (`clientServesActiveAccount()` in `src/lib/active-client-account.ts`).

## Review Focus

1. **On a network that reaches the mail server but fails Android's internet probe, sends go out immediately and queued sends replay.** With no network interface at all, sends still queue. Owned by Task 1, tests `a reachable server counts as online despite a failed internet probe` and `no interface means offline`.
2. **An iCal feed sync that started before an account switch never deletes or writes events in the new account's calendars.** Owned by Task 3, test `a sync interrupted by an account switch writes nothing`.
3. **A non-active account's push subscription picks up a changed Inbox-only filter at its next renewal.** Owned by Task 4, test `detached renewal rewrites a changed filter`.
4. **An undone quick rule does not come back into the Settings screen** after the refetches land out of order. Owned by Task 5, test `a stale fetch does not overwrite a newer one`.
5. **Hardening never sends a queued message where it would not have before.** That covers the Outbox wording, the backoff and the corrupt-row changes. Owned by Task 6.

### Task 1: Treat a reachable mail server as online

**Files:**
- Modify:
  - `src/stores/network-store.ts`;
  - the request path in `src/api/jmap-client.ts`, where every JMAP and blob request resolves or fails (`authenticatedFetch` / `request`, around `:675-764`).
  - Check each consumer of `useNetworkStore(...).online`: `App.tsx`, `src/stores/outbox-store.ts`, `src/stores/email-store.ts`, `src/lib/send-queue-replay.ts`, `src/screens/OutboxScreen.tsx`, `src/screens/EmailListScreen.tsx`, `src/screens/ComposeScreen.tsx`, `src/components/email/QuickReplyBox.tsx`, `src/components/OfflineBanner.tsx`, `src/lib/network-error.ts`.
- Test: `src/stores/__tests__/network-store.test.ts`

**Interfaces:**
- `NetworkState` gains:
  - `serverReachable: boolean | null`: `null` until the first request settles; `true` after any HTTP response from the mail server, whatever its status; `false` after a transport failure (`NetworkError`, a fetch `TypeError`, or `RequestTimeoutError`);
  - `noteServerResponse()`;
  - `noteServerUnreachable()`.
- `online` becomes:
  - `connected && (isInternetReachable !== false || serverReachable === true)`;
  - with no interface (`isConnected === false`), `online` is `false` whatever `serverReachable` says.
- When `connected` goes from `false` to `true`, reset `serverReachable` to `null`, because a new network says nothing about the server.
- Keep `connected` as it is. Keep the default `online: true` before NetInfo reports.
- `jmapClient` calls the two notes. The store must not import the client; use a setter or an injected callback, so there's no import cycle.
- A `serverReachable` flip from `false` to `true` that makes `online` go from `false` to `true` must fire the same flushes as a NetInfo online edge. App.tsx already watches `online`; check that it does.
- `isTransientNetworkError` reads the new `online`.

- [ ] **Step 1: Write the failing tests.**
  - `a reachable server counts as online despite a failed internet probe` (Review Focus 1): connected, `isInternetReachable: false`, then `noteServerResponse()` gives `online === true`.
  - `no interface means offline`: `isConnected: false` stays offline after `noteServerResponse()`.
  - A transport failure after a failed probe gives offline.
  - A new connection resets `serverReachable`.
  - The probe being `null` keeps today's behaviour.
- [ ] **Step 2: Run them to verify they fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run them to verify they pass.**
- [ ] **Step 5: Commit** `fix: count a reachable mail server as online when the internet probe fails`
